## Blockers
<!-- - [ ] <description> (check off when resolved) -->
- [ ] `main` has no server-side protection: GitHub Free blocks rulesets and branch protection on private repos (API 403). Until the repo goes public, `.claude/settings.json` deny rules and a local `.git/hooks/pre-push` guard it. When the repo is made public, add a ruleset on `main`: block deletion, block non-fast-forward pushes, require a pull request, repo owner on the bypass list.
- [x] Golden VM images need a manual CachyOS install from the ISO (Calamares) for each of Limine+LUKS and Limine plain; the user runs these once (task 03).
- [x] Qt 6.12 palette collision (decided 2026-10-21: task 16 bridge): the shell fix #14553 (`b83d3df0`) is not in v4.0.6 and its 4.0.4 backport #15265 was closed unmerged, while CachyOS ships qt6-declarative 6.12.0. A plain 4.0.6 install on CachyOS is expected to show shell surfaces without colours. Decide before task 10: patch the shell after each `omarchy` transaction (juliankgp's approach), carry the #14553 diff as a reviewed patch, or wait for a stable release containing it.
- [ ] Saved identity copy can go stale: CachyOS's own `cachyos-branding` script (run by `cachyos-branding.hook` on `cachyos-hooks` upgrades) sed-edits `/etc/os-release` with CachyOS values. If CachyOS changes those values, `/var/lib/cachyos-quattro/identity/os-release` keeps the old text and the next `omarchy-settings` upgrade restores it. Proposed fix (task 11 `update`, or a small hook after `cachyos-branding`): refresh the saved copy whenever `/etc/os-release` has `ID=cachyos`. verify only checks `ID=cachyos`, so it does not flag this.
